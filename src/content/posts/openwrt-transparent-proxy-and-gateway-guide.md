# 软路由与旁网关透明代理实战指南：彻底解决 OpenWrt/iStoreOS 下的 DNS 死循环、IPv6 泄露与全屋分流调优

为了让家里的智能电视（Apple TV、索尼电视）、游戏主机（PS5、Switch）、手机、平板以及智能家居设备实现“免客户端、开机即用”的全球网络加速与隐私防护，越来越多的极客和家庭用户选择了搭建 **软路由 / 旁网关（如 OpenWrt、iStoreOS、RouterOS）**。

然而，在满心欢喜完成配置后，许多人却迎来了全家人的网络吐槽大会：

> ❌ **国内网络反而变卡**：微信图片发送缓慢，淘宝、京东刷新转圈，国内银行 App 甚至误提示“当前处于境外网络拒绝登录”；  
> ❌ **智能家居大面积失联**：米家扫地机、摄像头或打印机频繁离线，局域网投屏找不到设备；  
> ❌ **神仙打架的“DNS 死循环”**：Dnsmasq、AdGuard Home 与代理内核（OpenClash / Mihomo / Passwall）互相转发，全屋频繁出现“DNS 解析超时”，网页要刷两次才开；  
> ❌ **IPv6 导致隐私全裸奔**：明明开了全屋透明网关，电视或手机一测，国内运营商的 IPv6 公网地址毫无阻拦地直接直连，真实物理地址完全泄露。

为什么单独在电脑或手机上挂客户端好好的，搬到路由器上就状况百出？

根本原因在于：**透明网关（Transparent Gateway）重构了局域网的数据包转发路径与 Linux 内核协议栈。** 旁路由单臂回环（Asymmetric Routing）、三层 DNS 嵌套劫持、NAT 穿透劣化以及未受管制的 IPv6 广播，都是导致网络翻车的致命元凶。

本文将深入 Linux 内核网络层与软路由拓扑，全面拆解常见陷阱，并指导你如何使用 **[一个机场 IP 工具箱 (ip.ygjc.cc)](https://ip.ygjc.cc/)** 对全屋多设备进行端到端的验收与调优。

## 一、 架构拆解：主路由与旁路由的致命陷阱

在家庭网络中，最常见的软路由玩法是 **“主路由负责拨号与无线 + 旁路由负责透明代理”**：

```
                    ┌────────────────────────┐
                    │      光猫 (Modem)       │
                    └───────────┬────────────┘
                                │
                    ┌───────────▼────────────┐
                    │  主路由 (如硬路由/爱快) │ ◄────────┐
                    │  IP: 192.168.1.1       │          │
                    └─────┬────────────┬─────┘          │
                          │            │                │
            局域网广播     │            │                │
   (Gateway: 192.168.1.2) │            │ 局域网实体连接  │ (未做伪装导致
                          │            │                │  异步路由丢包)
                          ▼            ▼                │
     ┌────────────────────────┐   ┌─────────────────┐   │
     │ 旁网关 (OpenWrt/iStore) │   │ 局域网终端设备  │───┘
     │ IP: 192.168.1.2        │   │ (手机/电视/电脑)│
     │ 运行 TProxy 透明代理   │   │                 │
     └────────────────────────┘   └─────────────────┘
```

### 1. 致命缺陷一：旁路由“单臂异步回环（Asymmetric Routing）”

许多用户只是简单地把手机的网关（Gateway）改成了旁路由的 IP（`192.168.1.2`），而主路由依然是 `192.168.1.1`：

- **去程**：手机发出的数据包发给旁路由，旁路由判定为国内直连，再丢给主路由发出（手机 -> 旁路由 -> 主路由 -> 互联网）；
- **回程**：互联网服务器返回的数据包回到主路由，主路由发现目标 IP 是局域网的手机（`192.168.1.100`），**直接跳过了旁路由，将响应直接推送给手机**（互联网 -> 主路由 -> 手机）；
- **结果**：手机发现自己发送的数据包走了网关 A，但收到的回包却来自网关 B，触发了 TCP 校验错误或被状态防火墙直接丢弃，导致网页极慢甚至卡死！

### 2. 致命缺陷二：三层 DNS 嵌套踩踏

在典型的软路由固件中，通常并存着：

1. **Dnsmasq**（OpenWrt 系统原生轻量 DNS，默认监听 53 端口）；
2. **AdGuard Home**（很多用户喜欢用来做全屋去广告，抢占 53 端口）；
3. **代理内核 DNS（Fake-IP）**（如 Clash Meta 的内嵌 DNS，监听 7874 或重定向 53 端口）。

如果上游与下游没有明确解耦，很容易出现：`终端 -> Dnsmasq -> AdGuard Home -> 代理核心 -> Dnsmasq` 的**死循环放大炸弹**，导致全屋 DNS 响应延迟从正常的 5ms 飙升至上千毫秒。

### 3. 致命缺陷三：IPv6 旁路击穿（Bypass）

国内各大运营商如今普遍下发公网 IPv6 前缀（如 `/60` 或 `/64`）：

- 主路由通过 SLAAC 自动向全屋设备通告了 IPv6 地址和运营商原生的 IPv6 DNS；
- 现代操作系统（iOS、Windows、Android）默认采用 **RFC 6724 规范（Happy Eyeballs 算法）**，只要发现存在 IPv6 路由，会**优先通过 IPv6 发起直连**；
- 旁路由通常只接管了 IPv4 流量，最终导致全屋设备的海外访问直接走主路由原生 IPv6 裸奔出去，代理彻底沦为摆设，真实地理位置暴露无遗！

## 二、 核心技术方案：打造完美旁路由的四大黄金法则

### 黄金法则 1：彻底根治异步回环（开启防火墙 NAT 伪装）

在 OpenWrt 终端执行以下配置，或者在【网络】->【防火墙】->【自定义规则】中加入：

```bash
# 核心：对进入 br-lan 接口发往局域网的流量强制执行 SNAT (IP 伪装)
iptables -t nat -I POSTROUTING -o br-lan -j MASQUERADE

# 如果使用的是较新的 OpenWrt 23+ (基于 nftables 架构)，在 nftables 规则中确保启用 masquerade
nft add rule inet fw4 srcnat oifname "br-lan" masquerade
```

- **原理**：旁路由向主路由转发数据包时，将源 IP 伪装成旁路由自己的 IP。这样主路由的回包必须先返回旁路由，再由旁路由发回终端，保证**来回链路严格一致（Symmetric Routing）**，彻底告别国内卡顿。

---

### 黄金法则 2：理顺全屋 DNS 链条（Fake-IP 极速分流）

推荐在软路由中推行最干净的高性能 DNS 架构，坚决弃用多层嵌套：

```
[局域网终端] ──(UDP/TCP 53)──► [代理内核 DNS (如 OpenClash / Mihomo)]
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
        【命中海外/代理域名】                        【命中国内白名单】
                  │                                   │
      直接下发 198.18.0.1/16 Fake-IP       转发至国内安全 DoH (如 223.5.5.5)
       (零延迟响应，阻断本地解析)               (获取真实最快 CDN 边缘 IP)
```

- **关键设置**：
  1. 将 OpenWrt 的 Dnsmasq 上游 DNS **仅仅指定为代理内核的监听端口**；
  2. 严禁在软路由中开启多重去广告插件与透明代理重定向互抢 53 端口；
  3. 开启 **Fake-IP 模式**，避免任何海外域名在路由器本地被明文解析，从根源上杜绝 DNS 污染与死循环。

---

### 黄金法则 3：驯服 IPv6（防止真实 IP 泄露）

针对家庭软路由，有两种彻底规避 IPv6 泄露的策略：

| 方案                                      | 操作方法                                                         | 优缺点分析                                                                            | 适用场景                               |
| :---------------------------------------- | :--------------------------------------------------------------- | :------------------------------------------------------------------------------------ | :------------------------------------- |
| **方案 A：全屋彻底禁用 IPv6（极力推荐）** | 主路由 DHCP 中关闭 IPv6 下发，WAN 口禁用 IPv6 拨号               | ⭐⭐⭐⭐⭐ **最稳妥省心**<br>彻底封堵任何泄露漏洞，网络排障难度降为 0                 | 绝大多数不需要外网访问 NAS 的家庭用户  |
| **方案 B：内核全量接管 IPv6 TProxy**      | 在 OpenClash / Mihomo 中开启 IPv6 代理支持，内核接管 IPv6 数据流 | ⭐⭐⭐⭐ **技术挑战大**<br>若节点不支持 IPv6 会导致海外连接超时，需保证落地机双栈完备 | 极客玩家、需利用公网 IPv6 远程串流用户 |

> **专家建议**：对于绝大多数用户，**直接在主路由中关闭局域网 IPv6 通告**，全屋纯运行 IPv4，是彻底杜绝分流失效最立竿见影的灵丹妙药。

---

### 黄金法则 4：全屋多设备精细化分流（MAC 地址黑白名单）

不是所有设备都需要走软路由翻墙。例如：家里的扫地机器人、空调伴侣、NAS 备份服务，或者老人的普通手机，如果误走代理反而容易触发异地报错或消耗机场流量。

在软路由中配置基于 MAC 地址的策略分流：

- **不走代理设备（DIRECT 模式）**：智能家居、监控摄像头、国行电视盒；
- **完全代理设备（PROXY / GLOBAL 模式）**：Apple TV、游戏主机、海外办公电脑；
- **规则分流设备（RULE 模式）**：个人主力手机与日常办公本。

## 三、 使用“一个机场 IP”对软路由环境全面验收

在软路由配置完成后，必须在局域网内选取两台具有代表性的设备（如**一台 iPhone 手机**与**一台 PC 电脑**），通过打开 **[一个机场 IP 工具箱 (ip.ygjc.cc)](https://ip.ygjc.cc/)** 进行实兵检验：

### 1. 全屋设备出口属性与 IPv6 泄露核验

访问 **[ip.ygjc.cc](https://ip.ygjc.cc/)** 首页：

- **国内直连 IPv4**：必须显示为你的真实宽带运营商（如中国电信/联通）；
- **海外出口 IPv4**：必须显示为你所设定的海外落地机，且运营商应为优质 ISP/原生节点；
- **重点排查“海外 IPv6”**：如果海外出口赫然出现你本地电信或移动的 IPv6，说明 **IPv6 发生严重旁路击穿**，必须立即按照“法则 3”予以封堵！

### 2. DNS 出口探针实测（验证是否发生解析死循环）

进入 **[DNS 出口检测 (ip.ygjc.cc/network/dns)](https://ip.ygjc.cc/network/dns)**：

- 观察四路权威探针（Surfshark、Fastly、BrowserLeaks 4/6）的响应速度；
- 如果响应迅速（1~2 秒内展示）且所有 Resolver 均为目标海外节点，说明全屋 Fake-IP 运转极佳；
- 如果页面转圈很久才出结果，甚至出现了国内运营商的本地 DNS，说明路由器内部存在 **Dnsmasq 循环解析或 DNS 泄露**。

### 3. 分流出口路径与延迟审计

进入 **[分流出口路径审计 (ip.ygjc.cc/network/exits)](https://ip.ygjc.cc/network/exits)** 与 **[连通性测试 (ip.ygjc.cc/network/connectivity)](https://ip.ygjc.cc/network/connectivity)**：

- 观察 Apple、Google、OpenAI、Bilibili 的并发响应延迟；
- 确认 Bilibili 完美直连且延迟低于 20ms，而海外服务稳定命中指定代理组。

## 四、 软路由排障自检清单（Checklist）

遇到全屋断网或局部设备翻车时，请依照下表快速排错定位：

| 故障现象                                   | 根源排查点                                  | 黄金修复方案                                                 |
| :----------------------------------------- | :------------------------------------------ | :----------------------------------------------------------- |
| **手机微信发图转圈、国内网页极慢**         | 旁路由单臂异步路由导致 TCP 回包被主路由跳过 | 在旁路由防火墙开启 `MASQUERADE` 伪装                         |
| **局域网设备间无法投屏互通**               | 旁路由将局域网私有流量误劫持进代理内核      | 将 `192.168.0.0/16` 等局域网私有网段加入直连白名单           |
| **全屋所有网页偶尔打不开，刷新又好**       | 多个 DNS 插件端口冲突引发死循环             | 关闭 AdGuard Home 的 53 重定向，由代理核心统一托管 DNS       |
| **测速正常，但电视 Netflix 提示代理**      | 智能电视请求走了未被代理的 IPv6 旁路        | 主路由彻底关闭 IPv6 局域网 DHCP 通告，只留 IPv4              |
| **PS5 / Switch 联机游戏 NAT 类型变为严格** | 软路由透明代理破坏了 FullCone NAT 打洞      | 在软路由防火墙中开启 FullCone 模块，或针对游戏机 IP 绕过代理 |

软路由是家庭网络的控制中枢。只有把底层的回环链路理顺、理清 DNS 拓扑并驯服 IPv6，才能真正释放千兆宽带的潜能，让全屋设备享受丝滑、稳定且无感的全球自由畅联！
